# 1.8.0 Fabric 1.20.1 验证记录

本轮目标：把公开 NeoForge Beta 3 的独立卡牌、模型、特效与战斗机制移植到 Fabric 1.20.1，去掉铁魔法系统，把四精灵与觉醒骷髅军团改为独立卡。

## 已完成的验证

- JDK 21 / Gradle 9.4.1 / Loom 1.16.1 编译，输出 Java 17 字节码和重映射 JAR。
- Java 17、Minecraft 1.20.1、Fabric Loader 0.16.14、Fabric API 0.92.6+1.20.1 的 GameTest：37 项必需测试全部通过。
- 完整卡牌目录：28 法术 + 7 部队／建筑卡；35 组实际工作台输入分别唯一匹配正确卡牌，无配方歧义。
- 真实卡牌部署的圣水扣费、镜像 +1 费用／12 级、元素类型、克隆 1 HP、NBT 保存和控制池验证。
- 骷髅军团 16 成员、3 HP／3 盾、每人一支支持军团、持久化 15 秒冷却；部署等待后，15 次同时剑击造成 45 基础伤害且不产生击退。
- 继承回归：卡牌伤害总量、护盾不溢出、武器不重复加伤、精灵跳跃／扫掠命中、9 段电击连锁、飞龙三阶段与控制重置、军团站位和存活逻辑、雪球颜色状态／减速时间线／朝向。
- 在新建隔离世界用最终重映射 JAR 完成独立客户端启动、实体模型／卡图／预览／特效渲染、保存并退出。日志带 `FABRIC18_CLIENT_QA_COMPLETE`。没有依赖 IDE 编译目录；测试 mods 仅为本模组和 Fabric API。
- 实际查看 PNG：模型、35 卡中的新卡显示、圆形范围、长条范围、双落点及法术表现。截图原文件随完整源码位于 `docs/validation`。

## 排查记录与限制

初次将临时测试平台建到新世界尚未正常照明的高空区段时，空平台在没有任何部队／卡牌／准星时也出现黑暗。改在已有原生超平坦地面搭建后，同一客户端的场景亮度正常；没有为掩盖问题而改动模型纹理或强制全局满亮。

一次 JDK 21 客户端测试出现 JVM 本地 C2 编译线程崩溃，日志指向 jvm.dll 中编译 CardRenderer.vertex。该记录不是可归因于 Java 异常的模组崩溃。目标游戏换用 Java 17 后，开发与正式包启动均完成；安装说明明确建议 Java 17。Gradle 构建本身仍用 JDK 21。

离线隔离客户端不使用真实登录令牌，因此可能报告认证／Realms 401；正常保存退出时可能有 ClosedChannelException。自定义实体的 vanilla DataFixer 缺省日志、原版山羊角声音事件 WARN、原版 emissive shader 可选 sampler WARN 不等于本模组资源加载失败。没有发现本版卡图／模型／音效文件缺失或 mixin 应用失败。

没有宣称通过整个用户整合包、多人联机、Sodium/Iris／光影、大规模压力、旧存档全部迁移或每种音效的主观听感验收。本次未替换既有 1.21.1 游戏实例，未录制视频、发送消息、关机或上传 GitHub。
