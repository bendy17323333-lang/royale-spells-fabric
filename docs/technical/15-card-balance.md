# 15 · 卡牌数值独立配置与 2026-09-08 换算

本章对应 `1.7.1-beta.3`。完整原作值、换算结果和来源见 [卡牌数值表](../../CARD-BALANCE.md)。本次仅改变独立卡牌路径及明确纳入调整的觉醒骷髅军团；铁魔法普通法术、四元素法杖和 MineClash 原单位不套用这组换算。

## 1. 换算边界

原作采用同一等级 11 级，小骷髅生命 81；模组小骷髅基准 3 点生命值。伤害、生命和普通治疗量均除以 27。范围按横向一格对应一个方块。护甲、抗性、免疫、队伍和伤害事件仍可以改变最终扣血，表中是防御结算前的基础量。

[CardBalance](../../src/main/java/dev/royalespells/CardBalance.java) 是唯一的卡牌参数入口。`Stats.hit11/hit12` 保存单次结算的原作量，`hit(level)` 才转换为 MC 数值。因此毒药存 92 而不是 736，万箭齐发存 122 而不是 366。使用浮点数保留小数，展示表才四舍五入。

[Spell](../../src/main/java/dev/royalespells/Spell.java) 的旧字段保留为铁魔法及旧工具使用的基础配置，不能将其中的 `radius` 和 `duration` 再称为全部卡牌的最终参数。`SpellEntity.radius/duration/hitAmount` 根据来源分派到不同配置。

## 2. 来源怎样跟随一次施法

[SpellEngine](../../src/main/java/dev/royalespells/SpellEngine.java) 的卡牌入口调用 `SpellEntity.create`，默认卡牌等级为 11。铁魔法入口随后设置 `IronSpell`、`IronLevel` 和 `DurationScale`；`cardCast()` 只有在铁魔法 ID 为空时返回真。

`CardLevel` 与其它施法参数保存在实体的 `SpellData` 复合数据内，通过现有实体同步传给客户端，写入 NBT。视觉层读取实体的 `radius()`，不凭手中当前物品猜测旧投射物的大小。玩家切换物品不会改变已经释放的法术。

镜像卡牌将 `CardLevel` 设置为 12，不再统一乘 1.1。多数 12 级数值来自实际等级表，避免原作取整造成的误差。虚空两个次级档和诱饵小僵尸的 12 级值是从已核对的当前基值按等级曲线推算，来源表明确标为推算值，不冒充已逐项读取的原作数值。铁魔法镜像沿用原先的等级、魔力和解锁检查。

## 3. 多段法术

| 卡牌 | 结算时间 / tick | 规则 |
| --- | --- | --- |
| 万箭齐发 | 4、12、20 | 三波，各 122/27；总 366/27 |
| 普通 / 觉醒小电 | 1；觉醒另加 21 | 首次半径 2.5；觉醒第二次半径 3，紫色电击 |
| 雷电 | 2、8、14 | 开始时选生命最高的三个敌人，每个至多一次；各 1057/27 |
| 毒药 | 1、21、…、141 | 八次，各 92/27；卡牌不再附带旧版减速 |
| 地震 | 1、21、41 | 对单位各 81/27，对本模组小屋各 283/27 |
| 飓风 | 1、11 | 两次各 84/27，场持续 22 tick；拉扯每 tick 更新 |
| 虚空 | 16、36、56 | 每波重新统计敌人数，三档伤害为 696 / 294 / 153，再除 27 |
| 藤蔓 | 1、21 | 最多三个目标，各次 153/27；总持续 40 tick |

`SpellEntity.tick` 对已经移除的实体直接返回，避免测试、第三方脚本或意外额外调用继续触发尾端伤害。正常世界仍由服务端实体生命期决定何时移除。

冰冻卡持续 70 tick（3.5 秒），原生铁魔法仍为 100 tick（5 秒）。末尾刷新状态时限制到剩余时间，避免固定刷新 3 tick 人为延长卡牌控制。冰冻动画冻结和电击短暂停顿仍由已有兼容层负责。

## 4. 精确移动效果

新增仅供卡牌使用的 `card_slow` 与 `card_speed` 状态。它们通过独立 movement-speed modifier 生效，不改 Minecraft 原生药水数值。`card_slow` 每级是 5%，雪球使用 amplifier=6 得到 35%，地震 amplifier=9 得到 50%。雪球蓝色状态仍持续 60 tick，动画速率仍为 0.65。狂暴卡使用 35% 移速，攻击加速继续由已有 `RAGED` 处理。

铁魔法雪球继续使用原有原生缓慢效果；毒药、地震、药水与雪球的可视状态保持独立。温暖会同时移除新的卡牌减速状态。Minecraft 的不同来源属性仍按原生合并规则叠加；这不是移植皇室战争的全部状态优先级系统。

## 5. 召唤物、武器与盾

卡牌召唤时，[CardBalance.apply](../../src/main/java/dev/royalespells/CardBalance.java) 同时写入生命、攻击、攻击周期、`RoyaleCardLevel` 与 `RoyaleCardAttackTicks`。视觉用石剑、铁剑和头盔的属性组件被置空；否则 Minecraft 会额外加上原版武器攻击力，实际输出就不等于换算表。

小屋的后续产兵和小僵尸诅咒的死亡转化都传递卡牌来源与等级。不能只调整最初生成的小屋或法术实体。克隆卡使用克隆卡自身的等级，不能把源单位的低等级攻击重新覆盖到镜像克隆上。

皇家卫队的卡牌盾使用独立、同步的 `CARD_SHIELD` 浮点数据；破盾的一击不会溢出到生命。零表示卡牌盾已破，负一是未使用卡牌盾的旧／铁魔法单位。客户端仅在零时隐藏模型 `shield` 部件，不影响其它实体。盾值写入 NBT。其它 mod 可以通过免疫和其伤害机制影响最终战斗，测试环境不能代替全部整合包组合。

觉醒军团是明确的例外：卷轴、法术书、号角和中立刷怪蛋召唤的小骷髅与将军都为 3 HP，盾为 3 HP，基础每击 3。旧存档的军团生命上限和盾值加载时封顶到 3；已经损失的生命不会被补满。军团共享冷却、每人一支的限制和幽灵存活规则保持原设计。

Minecraft 的 `MAX_HEALTH` 属性下限是 1。因此克隆体保持 1 HP，不能假称实际生命是 1/27。这里是明确的引擎适配例外；所有有伤害的卡牌仍能一击击杀正常克隆体。生命非常低的克隆不会因治疗而突破这一上限。

## 6. 命中形状、预览与特效

圆形法术使用水平圆柱查询：横向半径 1:1，保留适合 MC 的有限高度区间。滚木与滚桶卡使用矩形预览；长度分别为 10.1 和 4.5，宽度分别为 3.9 和 2.6。实际滚动物体逐 tick 扫过路径，并裁掉起点前和终点后的命中，避免原胶囊端点让射程超长。

只有圆心跟随落点地形，轮廓顶点不逐点贴合树叶或台阶；否则用户曾遇到的范围圈扭曲问题会复发。标准屏幕十字准星也不跟着世界预览变形。卡牌预览、箭雨落点、虚空场、毒药场和小电第二击均读取所属效果的配置。

火球的弹体尺寸并不等于伤害半径；命中时的火星散布和爆燃范围读取 `e.radius()`。滚木的木头长轴调到 3.9 格，仍绕与前进方向垂直的水平轴滚动。桶体保留原来的可读体积，由预览边界表达完整伤害宽度。

墓园采用 12 次生成、半径 4；MC 落点采用平均半径 3.3 的八个固定外围锚点重复分布。顺序和地面投影是本模组适配，不声称逐像素复刻原作竞技场的完整刷出坐标。

## 7. 如何验证下一次更新

[CardBalanceTests](../../src/main/java/dev/royalespells/test/CardBalanceTests.java) 在世界里执行完整施法，检查总扣血而不只比较常量。覆盖生命、持剑实际伤害、盾牌溢出、镜像转化和克隆、旧军团存档、雪球状态、卡牌／铁魔法配置和额外 tick。

原有测试继续覆盖三目标雷电、第二次小电的环形边缘、同 tick 十五只骷髅命中、实际寻路、幽灵分散、铁魔法施法与召唤交互。半径改变后必须同时检查命中边缘、预览和特效；只改技术表或截图不代表机制已更新。

参见本次 [验证记录](../../VALIDATION-1.7.1-beta.3.md)。客户端截图检查的是实际加载的最终 JAR；它不能保证任意光影、网络延迟、服务器配置或其它 mod 的组合都完全等效。
