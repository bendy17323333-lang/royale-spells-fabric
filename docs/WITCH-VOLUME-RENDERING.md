# 女巫世界内体积魔法渲染

本档案说明 1.9.1 使用的女巫体积特效与帧间连续性实现。密度雾继承 1.9.0 第三次重构的设计；本轮修复客户端位置与生命周期采样。它描述代码与验证方法，不代替实际客户端视觉验收。普通/觉醒女巫的攻击、伤害半径、召唤、归魂与治疗时机仍由服务器实体控制；仅攻击弹速由 0.6 提高为 0.72 格/tick。

## 设计与数据来源

目标是中心聚亮、边缘暗紫并逐渐变薄的连续雾团，不使用屏幕贴图、面向相机的粒子平面、实体叶片、重复圆泡或长期魔法圆环。原作影像证据与研究限制见 `research/witch-2026-10-10.md`。亮芯颜色保留粉紫色，不能用白色过曝模拟亮度；普通法球使用同系紫色是美术一致性选择，并非已独立确认普通原作弹体的精确逐帧颜色。

代码入口：

- `client/WitchMagicRenderer.java`：只读实体状态、收集真实尾迹、生成每个体积的参数。
- `client/WitchVolume.java`：资源重载注册、深度复制、GPU 状态隔离、LOD、逐体积即时绘制。
- `assets/royalespells/shaders/core/witch_volume.{json,vsh,fsh}`：闭合代理体、射线裁剪和三维密度积分。

## 世界坐标与真实命中

法球飞行期间使用 `WitchBolt.getPosition(partial)`。命中状态与 `impactPosition()` 在同个 metadata 包同步；若此前核心仍因网络插值落后，渲染器从最后实际 GPU 位置用最多两 tick 的单调补程接到爆点，再切换命中雾。爆点始终是服务器确认的碰撞位置，伤害、声音与效果到期不延后；命中时钟在补程期间继续计时。实际绘制样本分别记录可见阶段、服务器阶段及收到命中时的原始位置差，不剔除补程帧来美化统计。

`WitchBolt.lerpTo` 将网络目标排队，在客户端 tick 内推进短插值；每个渲染帧再使用 partial 取连续显示位置，避免网络包在帧中直接改变位置端点。尾迹记录这些真正渲染过的帧位置，最多 96 个缓存点、最多两格攻击尾雾，再按弧长重采样成七个 GPU 节点。镜头重新进入视锥或大幅瞬移时清除过期历史。片元着色器将相邻节点之间的线段转为连续横截面密度，并让宽度、浓度沿整个尾部逐渐减小。轻微上浮与偏流只改变烟雾密度；不改变实际轨迹或判定。

命中生命周期首次收到元数据时用同步年龄校准本地起点，此后用单调的 `tickCount + partial` 时间轴推进，不在每帧重新计算 `impactAge + partial`。这修复了本地 tick 和网络 tick 边界不同步时的阶段倒退；真实碰撞点仍以服务器同包同步数据为准，最后飞行至碰撞点的接缝单独观测。

每个体积仅做一次世界位置减相机位置。Fabric `WorldRenderContext` 的矩阵栈已包含相机旋转；不额外乘一次相机/RenderSystem 旋转。投影和逆投影均取该回调同一帧的数据。

左掌蓄力使用模式 5：WitchRenderer 在本帧模型动画后捕获 left_forearm 的真实矩阵，局部偏移 (0, 4/16, -2/16)。1.9.2 起右手拄杖、左手施法，法杖不是蓄力或发射挂点。缓存每帧清空，离屏单位不沿用旧锚点。完整现行契约见 [特效交接手册](technical/16-witch-vfx-handoff.md)。

## 闭合代理几何与体积积分

几何是具有外向面顺序的六面包围盒，正面剔除后仅光栅化退出表面。因此同个像素不会把前后面重复混色，相机在体积内部也有效。包围盒本身不着色；片元从相机到盒子退出位置计算射线与包围盒的解析交点。

密度场由连续的低频形变、两层平滑三维噪声和衰减包络构成。中心亮度场比外侧密度场更集中。命中使用从中心展开的**实心密度区域**，而非空心环；展开后流动上浮、降低光核强度、逐渐失去密度并透明消散。归魂与到达使用同一体积系统，到达的极短内核偏薄荷绿；角色本身的回血闪色仍由角色 renderer 实现。

每一步按 Beer–Lambert 透射率计算：

```
sampleAlpha = 1 - exp(-density * stepLength * extinction)
color += remainingLight * sampleAlpha * localColor
remainingLight *= 1 - sampleAlpha
alpha = 1 - remainingLight
```

输出颜色除以最终 alpha，得到普通 SRC_ALPHA / ONE_MINUS_SRC_ALPHA 混合需要的直通 RGB，避免重复预乘。所有颜色均有上限，无加法白色壳，无 Bloom 依赖。体积内部从前向后积累，独立体积之间按远到近绘制。

## 场景深度与状态恢复

世界渲染在 `WorldRenderEvents.LAST` 执行，位于普通实体与 Fabulous 透明合成之后。先提交仍待绘制的 buffer，然后每帧最多复制一次主渲染目标的深度到**独立** `TextureTarget`。禁止边写一个 FBO、边采样该 FBO 正在使用的深度附件，否则属于未定义的反馈。

每个像素用实际 FBO 尺寸求 UV，把深度值通过本帧逆投影恢复到 view-space，再用逆体积矩阵还原局部场景坐标。射线积分终点不得越过此坐标，末端 0.055 格做柔和交界。体积不写入深度，因而不会留下看似透明却裁掉玩家模型的面。

复制深度会临时改 FBO 绑定；代码重新绑定主目标后绘制，并在 `finally` 还原原 draw/read FBO、viewport、depth test/write、cull 状态和模式、blend 函数和方程、着色器选择、纹理单元 0 绑定及此前 active 单元。深度目标创建/调整尺寸前强制切至单元 0。窗口尺寸改变和资源重载会重建深度目标，退出客户端销毁目标。

`SceneDepth` 采样器使用独立名称，因为 Minecraft 的即时绘制会写入 `Sampler0...Sampler11`。尾迹使用 `Tail0...Tail6` 独立 vec4 uniform，避免 Minecraft JSON uniform 数组类型误匹配。每个体积设置参数后立即绘制，不在共享 RenderType 队列里等待其他实体覆盖参数。

## 性能预算与诊断

- 最多选择最近 40 个可见体积，然后再以远到近排序。
- 12 格内 36 步，26 格内 26 步，更远 18 步；减少粒子设置进一步降低到至少 14 步。
- 估计覆盖像素与积分步数；超过软预算降低到 14 步，超过硬预算跳过远处体积，优先保留近处。
- 透射率低于 0.015 提前结束积分；低于阈值的片元不输出。
- 只光栅化世界体积代理覆盖的像素；没有每个实体一次全屏后处理。
- 相同尾迹噪声在整个线段循环外计算。

资源加载成功输出 `WITCH_VOLUME_SHADER_READY`。实际发生绘制后才输出 `WITCH_VOLUME_ACTIVE`，包括本帧体积数、步数合计、累计 draw 数、深度尺寸与纹理 ID。该日志证明程序走过了体积绘制路径；不能单独证明画面合格或帧率可接受。

1.9.1 的 `visualSample` 只记录真正 GPU 提交后的世界锚点和 shader 时间，每帧清空。客户端 QA 在世界帧结束时写入 `witch-visual-continuity.csv`；打包时独立复算逐帧时钟、位置阶梯和命中阶段连续性。计数阈值、62 张图像集合与验证限制见 [1.9.1 技术增量](WITCH-1.9.1.md)。它不等价于多人网络抖动测试或 FPS 提升证明。

验收应包括实际游戏的飞行正侧/斜视、命中多时刻、地形与生物遮挡、镜头进入雾体、多个法球重叠、窗口 resize/资源重载。正面亮芯、外围暗雾、无白色过曝及无离散圆泡均需直接审图。最终性能需在相同摄像机、实体数量和画质设置下比较，不能以静态截图代替 FPS 测量。
